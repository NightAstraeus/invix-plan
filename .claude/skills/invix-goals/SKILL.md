# Ревью целей

## Проверка формулировок (`strategy/GOALS-2026-Q4.md`)
Для каждой строки:
- **Критерий проверяем «да/нет»?** «Стабильная печать» — нет; «три печати > 5 ч без смещений» — да.
- **Ответственный один и из `team/TEAM.md`?** Нет ответственного — цель не принята.
- **Веха с датой в `ROADMAP.md`?** Нет даты — заглушка `[[ПРОВЕРИТЬ: дата]]` и Issue.
- **Нет сумм и цен** (`grep -En "руб|₽|тыс\." strategy/`).
- **Нет слов из стоп‑листа** («серийный», сравнения с импортом).
- **Это цель, а не задача?** Задача — в бота.
Выдать список замечаний по ID, предложить правки, применить после «да».

## Закрытие квартала (декабрь)
1. По каждой цели: `достигнута` / `снята` / переносится — с причиной в одну строку.
2. Таблицу квартала переместить в `strategy/archive/GOALS-2026-Q4.md` (папка создаётся только здесь, строка в `DECISIONS.md`).
3. Из `strategy/GOALS-2027.md` и перенесённых целей собрать `GOALS-2027-Q1.md` по тому же формату.
4. `STATE.md`: новые цели, следующий шаг. `ROADMAP.md`: прошедшие вехи — в раздел «Прошло».
5. Коммит: «Квартал Q4 2026 закрыт: N достигнуто, M перенесено, K снято».

## Чего не делать
- Не переписывать критерии так, чтобы цель «вдруг достиглась».
- Не плодить цели: 5–7 на квартал на оба проекта.

# Недельный ритм

Файл недели — `weekly/ГГГГ-WNN.md` (ISO‑неделя, шаблон в `weekly/README.md`). Режим выбирается по дню недели или по слову владельца: «план» / «разбор».

## Понедельник — план
1. Прочитать `STATE.md`, `strategy/GOALS-2026-Q4.md`, `strategy/ROADMAP.md` (вехи на 14 дней), `tasks/MIRROR.md` (просроченные и задачи без срока), `gh issue list` здесь и `gh issue list -R NightAstraeus/printer-config`.
2. Предложить **не больше трёх приоритетов**, каждый → `Ц-Q4-NN`. Критерий выбора: ближайшая веха, цель в статусе `риск`, просрочки в боте.
3. Для каждого приоритета — что конкретно должно произойти к пятнице и кто это делает.
4. Владелец правит и утверждает. Записать раздел «Понедельник» в файл недели.
5. Нужны задачи команде — не писать их в файл, а сформулировать для бота (текст, исполнитель, срок, проект) и попросить владельца завести; в файл — `#id` после создания.
6. Коммит: «Неделя NN: план».

## Пятница — разбор
1. По каждому приоритету понедельника спросить владельца: сделано / не сделано / почему. Сверить с `tasks/MIRROR.md`, если он свежий.
2. Решения → строки в `DECISIONS.md` (дата — решение — кто/почему).
3. Статусы целей: предложить изменения (`в работе` → `риск`, `достигнута`), применить после «да» в `GOALS` и отразить в `STATE.md`.
4. Новые вопросы и развилки → Issues по шаблонам `question` / `decision`.
5. Последняя строка — «Следующий шаг руководителя» — скопировать в `STATE.md`.
6. Коммит: «Неделя NN: разбор».

## Правила
- Приоритетов три, не пять. Если владелец хочет больше — спросить, что выкинуть.
- Не было разбора — так и записать «разбора не было», не восстанавливать задним числом.
- Финансы в приоритетах не фигурируют суммами («подписать акт» — да, «получить N руб.» — нет).
- Жёстко и коротко: факты, причины, следующий шаг. Без похвал и воды.
